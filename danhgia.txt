# CÔNG VIỆC CẦN KHẮC PHỤC — DỰ ÁN TEST TÂM LÝ

## 1. Mục tiêu

Rà soát và khắc phục các vấn đề hiện tại để bảo đảm WinForms có thể đăng ký, đăng nhập, gọi backend và truy cập Firebase an toàn.

Đọc `FIREBASE_BACKEND.md`, `huongdan.md`, `SETUP.md` và báo cáo `danhgia.txt` trước khi thực hiện.

Không tạo lại dự án, không thay đổi kiến trúc đã thống nhất và không làm mất giao diện hiện có.

## 2. Công việc cần thực hiện

### Công việc 1: Thống nhất cấu hình cổng backend

- Kiểm tra `launchSettings.json`, `appsettings.json`, `appsettings.Development.json`, `SETUP.md`, `.env.example` và `Classes/KetNoi.cs`.
- Thống nhất địa chỉ API giữa backend và WinForms.
- Không mặc định cổng 5000 nếu backend thực tế đang chạy ở cổng khác.
- Kiểm tra cấu hình HTTP/HTTPS và chứng chỉ HTTPS trong môi trường phát triển.
- Tách địa chỉ API khỏi mã nguồn nếu phù hợp để dễ thay đổi giữa môi trường phát triển và triển khai.
- Build backend và kiểm tra endpoint health thực tế.

### Công việc 2: Bổ sung `.gitignore`

- Tạo `.gitignore` tại thư mục gốc nếu chưa có.
- Loại trừ `bin/`, `obj/`, `.vs/`, các file cấu hình môi trường và thông tin xác thực nhạy cảm.
- Kiểm tra `api_key.txt` và các file chứa cấu hình Firebase trước khi quyết định có đưa vào Git hay không.
- Không đưa Service Account JSON, private key, mật khẩu hoặc token lên GitHub.
- Không xem Firebase Web API key là mật khẩu; tuy nhiên cần quản lý cấu hình đúng cách và kiểm tra các hạn chế bảo mật phù hợp.
- Nếu file nhạy cảm đã được Git theo dõi, xử lý việc theo dõi đó thay vì chỉ thêm tên file vào `.gitignore`.

### Công việc 3: Tích hợp đăng ký và đăng nhập WinForms

- Kiểm tra `Classes/KetNoi.cs`, `frmDangNhap.cs`, `frmDangKy.cs` và các file Designer liên quan.
- Sử dụng `FirebaseAuthentication.net` để triển khai đăng ký/đăng nhập bằng Email/Password theo cấu hình Firebase hiện có.
- Gắn đúng event handler cho các nút đăng ký và đăng nhập.
- Kiểm tra dữ liệu đầu vào, mật khẩu xác nhận, thông báo lỗi và trạng thái đang xử lý.
- Sau khi đăng nhập thành công, lấy Firebase ID token và dùng token đó khi gọi endpoint cần xác thực.
- Gọi backend qua `KetNoi.cs`, gửi token bằng header `Authorization: Bearer <token>`.
- Không lưu mật khẩu dạng văn bản trong Firestore hoặc log.
- Không tự ý lưu token lâu dài nếu chưa có thiết kế quản lý phiên và vòng đời token phù hợp.
- Giữ nguyên giao diện, tên control và cấu trúc thư mục hiện tại nếu không có lý do kỹ thuật bắt buộc phải thay đổi.

### Công việc 4: Rà soát và sửa endpoint Firestore

- Kiểm tra `FirestoreController.cs`, đặc biệt endpoint `/api/firestore/ping`.
- Theo báo cáo đánh giá, endpoint GET hiện có thao tác ghi dữ liệu.
- Nếu endpoint thực sự ghi dữ liệu, chuyển sang POST hoặc thiết kế lại endpoint theo đúng mục đích.
- Cập nhật client, tài liệu và file `.http` nếu đường dẫn hoặc HTTP method thay đổi.
- Phân biệt rõ endpoint health chỉ kiểm tra trạng thái backend với endpoint kiểm tra kết nối Firestore.
- Không để endpoint kiểm tra thử tạo dữ liệu liên tục trong database thật.
- Endpoint truy cập Firestore phải có xác thực và phân quyền phù hợp.

### Công việc 5: Rà soát xác thực và phân quyền backend

- Kiểm tra `FirebaseAuthMiddleware`, `TokenVerifier`, `FirebaseService` và các controller.
- Xác minh mọi endpoint yêu cầu đăng nhập đều từ chối token thiếu, sai hoặc hết hạn.
- Đánh giá việc dùng cơ chế authorization tập trung của ASP.NET Core thay cho việc mỗi controller tự kiểm tra token.
- Không tin UID hoặc vai trò do client tự gửi lên.
- Xác định người dùng từ Firebase ID token đã được xác minh.
- Kiểm tra quyền truy cập dữ liệu để người dùng không thể đọc hoặc sửa hồ sơ, kết quả bài test của người khác.
- Không cho phép người dùng thường thực hiện chức năng quản trị.
- Tiếp tục sử dụng ADC trong môi trường phát triển; không nhúng thông tin xác thực server vào WinForms.

### Công việc 6: Rà soát các thư viện NuGet

- Giữ `FirebaseAuthentication.net` trong WinForms nếu đang dùng cho đăng ký/đăng nhập.
- Kiểm tra toàn bộ mã nguồn WinForms trước khi gỡ `Google.Cloud.Firestore`.
- Nếu WinForms không sử dụng trực tiếp thư viện này, gỡ khỏi project WinForms để tránh phụ thuộc không cần thiết.
- Giữ thư viện Firestore cần thiết trong backend.
- Chỉ gỡ package sau khi xác nhận đúng project và kiểm tra các tham chiếu liên quan.
- Không gỡ package chỉ vì tên thư viện giống nhau giữa hai project.

### Công việc 7: Dọn cấu hình mẫu và bổ sung kiểm thử

- Xóa phần `weatherforecast` mẫu trong `TestTamLy.Api.http` nếu không còn sử dụng.
- Kiểm tra tài liệu `SETUP.md` và `.env.example` sau khi sửa cấu hình.
- Build cả backend và WinForms.
- Kiểm thử endpoint health, đăng ký, đăng nhập, token hợp lệ, token không hợp lệ và truy cập Firestore.
- Kiểm tra trường hợp mất mạng, timeout và lỗi server.
- Bổ sung automated tests phù hợp khi có thể, ưu tiên các phần xác minh token, authorization và nghiệp vụ quan trọng.

## 3. Thứ tự thực hiện

1. Kiểm tra mã nguồn và thống nhất cổng backend.
2. Tạo `.gitignore` và rà soát file cấu hình.
3. Tích hợp đăng ký/đăng nhập WinForms.
4. Sửa endpoint Firestore và rà soát xác thực/phân quyền.
5. Rà soát package NuGet, dọn template.
6. Build và kiểm thử toàn bộ luồng WinForms → Backend → Firebase.

Có thể thực hiện các việc độc lập cùng đợt nếu an toàn, nhưng phải xử lý lỗi nền tảng trước khi kết luận tích hợp thành công.
